# T-075: preserve approved character assets (immutable store, generator cannot overwrite)
Implementer: Claude (cloud) · lane A (process/tooling) · path A · branch `t-075-claude-approved-assets` from `origin/staging`
Owner decision 2026-11-17: approved Blender character assets must be preserved and reusable, never overwritten by
the generator.

## Today
- `pipeline/charsys/asset_store.py` already implements an immutable versioned store
  (`assets/characters/<id>/versions/<ver>/` with `<id>_master.blend`, `.glb`, spec, manifest with sha256,
  `index.json` pointers, read-only files, `publish/approve/verify/restore`).
- Only boy **1.0.0** is published (pointer `reference`; `approved` is null). The currently approved versions
  (`docs/evaluation/characters/fidelity_baseline.json`: boy 1.1.0, girl 0.10.0 intermediate) exist only as
  "regenerate from pinned code", protected by the regression guard.

## Acceptance criteria
1. **Publish** the current approved versions into the store: boy 1.1.0 and girl 0.10.0, built from their pinned
   specs/modules; manifest hashes recorded. Set `approved` per the owner's recorded decisions
   (`docs/process/OWNER_DECISIONS.md`: boy 1.1.0 "current approved"; girl 0.10.0 approved as intermediate; record
   that wording in the notes). Third character: nothing to publish yet.
2. **Generator guard:** any build/publish path refuses to write into an existing published version folder or to
   reuse a published version number (error, non-zero exit); new builds go to a build dir or a new version only.
   Test: an attempted overwrite fails and leaves the files byte-identical.
3. **Integrity check:** `tools/check_assets.py` verifies every published version (hashes vs manifest, read-only
   intent, pointers point to existing versions, no published file modified in the diff vs `origin/staging`).
   (`assets/characters/*/versions/` is already a guarded path, added by the Supervisor.) Wiring into `tools/check_all.py` is a separate small
   step after T-061 releases that file (report the exact diff).
4. **Reuse:** shots and evaluations can use the stored approved master directly (linked, read-only; `episode.py`
   rules), selected by cast `"current"`, instead of regenerating; regenerate-and-compare remains as the
   determinism check (hash or regression image match against the stored version). Document the rule in
   `docs/process/` (one short section).
5. Size: report per-version size; keep within GitHub limits (no file > 95 MB); if the `.glb` is not needed for
   reuse, say so instead of storing it.
6. Full gate (`tools/check_all.py --full`) passes; approved renders are unchanged (regression guard).
