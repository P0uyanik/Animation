## Acceptance criteria
1. Shard the Blender tier into 4-6 parallel jobs (pattern: the per-character regression matrix). Every test that ran
   before still runs with the same arguments and thresholds. The Gate verdict requires ALL shards; a missing, cancelled
   or skipped shard is FAIL, never pass.
2. Prebuilt dependency image (or an equivalent pinned cache) with apt packages, the bpy wheel and the toolchain, so jobs
   stop installing from the Ubuntu mirrors. Pin versions, record the image digest, keep a working fallback to the
   current install path. Same for the backup workflow's fast-tier step.
3. Cancel superseded runs (concurrency group per branch, cancel-in-progress) for task and integration branches ONLY;
   never main/staging, the backup workflow, nightly Windows or scheduled runs.
4. Batch promotions: document the procedure (one gate run covers several finished tasks) in `docs/process/GATE.md`.
5. Per-test durations in the gate report (JSON + summary); `run_logged()` already returns the time.

each on a throwaway branch `probe/t-127-*` (never merged), that still turn the gate red with the new setup: at least
one Blender test, one C++ test, one Python test, one regression. (c) Two consecutive green runs on the same commit.
(d) Before/after wall-clock and runner-minutes (parallel jobs use more minutes per run; report it).
Roll out with the old path still available until (a)-(d) pass.
