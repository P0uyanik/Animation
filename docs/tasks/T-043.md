# T-043: spec parts, per-feature generator versions, shared helpers out of body_v6
Lane B · path A (refactor, zero visual change) · branch `t-043-claude-spec-versions` from `origin/staging`

## Goal
Versioned shared systems (owner decision 2026-11-17): a character spec pins the version of every generator, preset
and the exporter it uses; released versions are immutable; new behaviour = new version. No character changes.

## Acceptance criteria
1. Spec schema: `generators: {body: "body_generic/1", face: "face_generic/2", groom: "groom/1", garment: "garment/1",
   materials: "presets/1", exporter: "export/4"}` (names as found in code). Specs may be split into parts
   (`identity`, `body`, `face`, `hair`, `outfit`, `materials`) composed by `spec.py`; existing spec files load unchanged
   (missing pins default to the versions they build with today, recorded explicitly).
2. Version registry `pipeline/charsys/versions.py`: each generator registers numbered versions; building with an
   unknown or retired version fails loudly. Replaces the single global EXPORTER_VERSION with per-feature versions,
   recorded in the export manifest.
3. Shared helpers used by new code move from `body_v6.py` (frozen: do NOT edit it) into
   `pipeline/charsys/body_helpers.py`; new and shared code imports them from there; body_v6 keeps its own copies.
4. **Zero change:** every character builds byte-identical fingerprints (`fingerprint_v2.py`, strict grid) and an
   identical engine export vs `origin/staging`; `verify_charsys.py` PASS; full gate PASS.
5. Tests: registry (unknown version fails, pins respected, two characters on different versions of one generator in
   one build session do not affect each other), spec part composition.
6. `docs/CHARACTER_SYSTEM_VERSIONS.md`: how to add a version, how a pin bump works (path B, owner approval).
