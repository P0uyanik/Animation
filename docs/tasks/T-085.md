# T-085: frozen engine renderer optional in the build (Phase A, round 2)

Implementer: Claude (cloud) · lane A · path A · branch `t-085-claude-renderer-optional` from `origin/main`.
Round 2 plan: `docs/process/ROUND2_PLAN.md` A1. Owner-approved 2026-11-18.

## Why
Embree is used only by the frozen preview renderer (`engine/render/pathtracer.cpp`, renderer frozen per TD-43).
Because it is a hard dependency, cloud implementers cannot build the C++ engine or run the full gate locally (14
relay reports). On Windows it is 1.4 h of the 1.8 h dependency build. The renderer stays frozen and must keep
compiling; it just must not be required.

## Acceptance criteria
1. CMake option `PLUSH_BUILD_RENDERER`, **default OFF**. With it OFF:
   - the engine core, animation, scene, bake and tests build and pass without Embree or OIDN;
   - no renderer target is built;
   - tests that need the renderer are skipped, and the skip is reported.
2. With it ON: identical behaviour to today, and the frozen renderer tests and regressions pass unchanged.
3. Embree and OIDN become optional dependencies: a vcpkg manifest feature, or a separate dependency set, that CI
   installs only for the renderer job.
4. CI:
   - the quality gate builds with the renderer OFF;
   - exactly **one** Linux CI job builds with it ON and runs the renderer tests, so it keeps compiling.
5. `tools/check_all.py` works in a fresh cloud session without Embree: the C++ build and tests PASS locally. Report
   timings.
6. No test loosened, no frozen file changed, no renderer source changed (only build wiring).
