# T-088: version-switch script (Phase A, round 2)

Implementer: Claude (cloud) · lane A · path A · branch `t-088-claude-version-switch` from `origin/main`.
Round 2 plan A4. Owner-approved 2026-11-18.

## Why
Making boy 2.0.0 and girl 0.11.0 current on 2026-11-18 needed 5 serial fixes, each costing a CI round:
- version specs not accepted by `tools/regression/tiers.py`;
- a presets pin inconsistency (`skin-felt/2` without a `presets/2` pin);
- a missing golden regression baseline;
- claim and approval timing;
- 8 to 18 per-file approval trailers.

## Acceptance criteria
1. `tools/version_switch.py --character <id> --version <x.y.z> --spec <path> [--overrides ...]` does all of the
   following in order:
   1. validates the spec (identity, generator pins resolvable; presets pin consistent with the preset ids used);
   2. builds deterministically and publishes into the asset store (refuses to overwrite);
   3. sets the `approved` pointer with the owner-decision note;
   4. updates the character's entry in `docs/evaluation/characters/fidelity_baseline.json` with the new score and a
      rebaseline note;
   5. writes the golden regression baseline;
   6. runs the cast check and the affected tests;
   7. prints the exact `Supervisor-Approved:` trailer block for every guarded path it touched.
2. `--dry-run` shows every step and file without writing.
3. Fails early with a clear message on any inconsistency found on 2026-11-18. Tests cover each of those cases with
   small fixtures.
4. Documented in `docs/process/ASSET_STORE.md` (one section).
5. Never touches other characters or published versions; the frozen-manifest and immutability checks stay unchanged.
