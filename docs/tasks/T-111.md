# T-111: Interaction architecture: object affordances and a verb library (round 3, design only)

Implementer: Claude (cloud, short-lived architect) · lane E · path A · branch `t-111-claude-interaction-design` from
`origin/main`. Owner-approved 2026-11-19 (`docs/process/OWNER_DECISIONS.md`, round 3 start).

## Why
Interactions are planned per verb in code (`engine/scene/interaction.*`, `collision.*`). Objects carry no data on
how to be held, and verbs have no shared phase/timing structure. Round 3 needs pick up, carry, pass and place built
on data, reusing T-097 reactions and the T-104 timing profile.

## Acceptance criteria
1. A design doc `docs/architecture/INTERACTION_AFFORDANCES.md`:
   - **Object affordances** in the asset format: grasp sites, hand shape, one or two hands, weight/size class,
     pivot, push/pull axis, deform mode. Include a JSON schema sketch and two worked examples: the e907 cup and one
     two-handed object.
   - **Verb library as data:** phases look / anticipate / approach / contact / manipulate / release / settle, with
     timing curves (from `content/timing/reference_timing.json`) and constraints.
   - **Mapping onto the existing planner:** `engine/scene/interaction.*`, `collision.*`, T-097 reactions and the
     T-104 timing profile. Say what is reused, what changes, and the migration path. Existing bakes must stay
     byte-identical until a verb is opted in.
   - **First verbs:** pick up, carry, pass, place, each with its phase table and failure cases.
   - **Fingers:** how T-051 finger grasps attach to the grasp sites.
2. Task files in the repo template (`docs/tasks/_TEMPLATE.md`), each with acceptance criteria, a disjoint
   write-set, tests and effort: `docs/tasks/T-112.md` (affordances + verb library implementation, split into
   T-112a/b if large) and `docs/tasks/T-051.md` (finger grasps).
3. Docs and task files only, no code. Read the code, don't change it.
