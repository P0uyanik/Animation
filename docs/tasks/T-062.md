# T-062: animation evaluations always use the current approved character versions
Lane A/C · path A · branch `t-062-claude-current-cast` from `origin/staging`

## Why
Owner 2026-11-17: animation tests and evidence still used old versions (boy 1.0.0, girl m3), so the combined quality
of the current characters was never assessed. Root cause: each shot names its cast explicitly and tasks copy older
shots; nothing resolves "the current approved version". The source of truth for current versions is the gate's
`docs/evaluation/characters/fidelity_baseline.json` (build spec + overrides per character; girl 0.10.0, boy 1.1.0).

## Acceptance criteria
1. `run_shot` supports a cast reference `"current"` (per character id) that resolves to the current approved version
   from `fidelity_baseline.json` (spec + overrides; published masters where the version is published), recorded in
   `run_shot.json` with the resolved version. Explicit versions keep working.
2. A shared set of **evaluation shots** (`content/scenes/eval/`): idle, walk, reach + touch, wave, hand-over,
   emotion sequence — using `"current"` for every built character (boy, girl; the third character once buildable).
   Animation tasks render their evidence from these (or derive from them).
3. A check in the gate (fast tier): evaluation scenes and new `docs/evaluation/**/shot*.scene.json` must not pin a
   non-current version unless marked `"legacy_reason"`; legacy engine unit-test packages (frozen `tests/data`) are
   exempt and documented.
4. Proof: e906-style wave/reach shot rendered with the current boy 1.1.0 and girl 0.10.0 (≤ 1 render, Cycles low
   samples + OIDN), next to the old-version render.
