## Why (evidence)
- Objects carry no data on how they are held; `graspShape` (`engine/scene/interaction.cpp`) guesses from the primitive.
- Verbs have no shared phase structure: anticipation, settle and gaze lead are authored per shot
  (`episodes/e907_exchange/make_shot.py`, e.g. `T.f("anticipation", "boy") // 2`).
- Design sections 2, 3, 4.1–4.3, 6.

## Acceptance criteria
1. **Golden first.** The first commit adds `tests/test_bake_golden.cpp` + `tests/data/golden/interaction_hashes.json`:
   SHA-256 of the generated clip and the engine `plush.shot_bake/1` output for every content scene with interaction
   actions and the `test_interaction.cpp` scenes, at the input SHA (design 6.3). It passes on every later commit.
2. `plush.asset/1` optional `affordances` block (design 2.2): parsed into `PropAsset::affordances`, validated (design
   2.2 rules), documented in `docs/ASSET_LIBRARY.md`. An asset without it loads exactly as before; an invalid block
   fails only a verb action that uses it. `content/assets/felt_cup.asset.json` gets the block of design 2.5; the e907
   golden hashes do not change.
3. `content/verbs/{pick_up,carry,place}.verb.json` (`plush.verb/1`, design 3.2) and the verb expander
   `engine/scene/verbs.{h,cpp}`: pure Json → Json pre-pass called once in `compileActions` before
   `planReactionActions`, only when an action has a verb type. Phases look / anticipate / approach / contact /
   manipulate / release / settle with beats via `TimingProfile::frames` and the fallbacks of design 3.3.
4. **Legacy equivalence test:** with no timing profile and no optional phases, `pick_up` + `carry` + `place` expand
   to primitive actions whose compiled clip is key-for-key identical to the hand-written `grasp` + `hold` + `place`
   (boy, girl and engine skeletons, as `test_interaction.cpp` `pickUpAndPlace`).
5. **Profile test:** with `"timing": "calibrated"`, phase lengths equal the profile beats x tempo (boy slower, girl
   quicker), look ends ≥ 2 f before approach starts, contact palm error ≤ 0.5 mm.
6. **Failure cases** of design 4.1–4.3 each return a structured error naming verb, character, prop and reason (one
   test each): hand full, prop held by another, unknown site/set, wrong hand, two-hand prop with one hand, out of
   reach, upright exceeded, place target occupied, non-rigid deform.
7. `look` gains optional `atProp` (prop middle); existing `target` / `atCharacter` unchanged.
8. One opt-in demo shot `episodes/e907_exchange/shots/s010_verbs/` (pick up, carry, place by the boy; current
   approved versions); animcheck timing rule: no new warnings. One cheap preview frame
   (`tools/review/recipe.py preview`), no strict sheet (technical task).
9. No test loosened; no frozen or published file changed; `s010`, `s010_calibrated` unchanged.
