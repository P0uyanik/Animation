# T-124: Render optimisation at 720p, measurement-driven (round 4, parallel)

Implementer: Claude (cloud, Opus 5.5) · lane E · path A technical · branch `t-124-claude-render-opt` from `origin/main`
(input SHA in the task prompt). Owner decision 2026-11-19 ~12:30Z (`docs/process/OWNER_DECISIONS.md`).

## Why
Final delivery is 720p (1280x720) at 24 fps with every frame rendered; no 1080p. GPU rental waits until this task is
finished, because every measured saving lowers every future render. Principle (owner): actual measurements, not a
target number. Report what each setting really costs and changes; the owner chooses.

## Acceptance criteria
Cloud CPU; record the machine; repeat runs to show variance; one shot (e907 `s010_verbs`, or the T-117 e910 shot if
it is on main) at 720p.
1. **Baseline and time breakdown** with the current final settings (128 spp, OIDN, adaptive, 12 bounces): per frame
   scene load/sync, geometry nodes / hair / fibre evaluation, BVH build, path tracing, denoise, save. Cost drivers by
   toggling one element at a time (hair/groom, fibre halo/fuzz, SSS skin, glasses/transparency, lights).
2. **Levers**, each alone, then the best combined:
   - samples 16/32/64/128 with OIDN; adaptive threshold; denoiser options (albedo/normal passes, quality/prefilter);
   - max and per-type bounces; clamping; light count;
   - Persistent Data and baked/cached geometry nodes and hair between frames (fixed per-frame cost);
   - hair/fibre LOD by on-screen size (silhouettes must not change);
   - static background rendered once and composited with a shadow catcher (still-camera shots);
   - reuse of identical hold frames, only where the bake shows nothing moves;
   - EEVEE vs Cycles on the same shot (comparison only); threads/tiles;
   - optional, measured only: 540p + upscale to 720p vs native 720p.
3. **Encoding**: lossless masters (16-bit PNG or EXR) encoded separately; at 720p/24 compare H.264 8-bit, HEVC 10-bit and
   AV1 10-bit: size at matched quality vs the master (VMAF/SSIM), banding on soft felt gradients, playback
   compatibility (phone, browser, YouTube).
4. **Quality evidence**: strict side-by-side 720p stills plus 100% crops (fibres, hair, eyes/pupils behind the
   glasses); short moving clips per setting (flicker, shimmer, denoiser smearing); objective metrics (difference vs a
   high-sample 720p reference, a temporal flicker measure) as supporting evidence only.
5. **Deliverable** in `docs/evaluation/rendering/T-124/`: table of measured s/frame and quality impact per setting;
   clips and sheets; proposed opt-in `final720` and `review` profiles; reproducible scripts. The owner approves before
   any profile becomes the default.

## Hard limits
No change to tests, thresholds, golden baselines or the CPU gate renders; no character, asset or spec changes; profiles
opt-in only (default render behaviour byte-identical); no force-push, no PR, no branch deletion. Keep committed media
small (short clips, JPEG sheets; no lossless masters in git).
