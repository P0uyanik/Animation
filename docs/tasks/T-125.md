# T-125: Automatic motion checks (flicker, popping, interpenetration)

Implementer: Claude (cloud, Opus 5.5) · lane E · path A technical · branch `t-125-claude-motion-checks` from the
integration branch in the task prompt. Owner decision 2026-11-19 ~13:10Z (independent of round 4).

## Acceptance criteria
Checks over baked and rendered shot frames, each reporting frame ranges plus a small evidence strip per issue:
1. **Flicker/shimmer**: temporal luminance noise per region (hair, fibres, skin, background), separating motion from
   noise (e.g. compare against a motion-compensated or held-pose baseline); denoiser output included.
2. **Popping**: sudden pose / vertex / transform jumps or one-frame discontinuities in joints, face controls and props
   (second-difference / jerk outliers on the bake, plus a mesh-level check where the bake allows).
3. **Interpenetration over time**: body-body, body-garment, hand-prop and character-character per frame, using the
   existing collision bodies and meshes.
4. First cases: e907 and the T-114 (e909) shot; T-117 (e910) when it exists. Thresholds come from measurements on
   current shots and are documented with the numbers.
5. Fixture tests in `tools/motion_checks/tests/`. Not wired into the gate; the Supervisor may wire it later. Existing
   tests are never loosened.

## Hard limits
No change to existing tests, thresholds, goldens, shots, characters or assets; no force-push, no PR, no branch deletion.
Committed media small (JPEG strips).
