# T-048: automatic branch cleanup workflow, fully tested
Lane A · path A · plan: docs/process/DELIVERY_PLAN.md §8.2 · branch `t-048-claude-branch-cleanup` from `origin/staging`

## Why
Cloud sessions cannot delete branches (proxy 403). About 40 fully merged branches remain. A GitHub Actions workflow
(GITHUB_TOKEN, contents: write) deletes them, but only under strict, tested conditions.

## Acceptance criteria
1. **Trigger:** push to branch `cleanup-request` containing `cleanup/REQUEST.json`
   (`{"mode": "dry-run"|"delete", "branches": [...], "requested_by": "...", "reason": "..."}`); also
   `workflow_dispatch`. No schedule, no wildcard deletion: only listed branches are considered.
2. **Selection (all must hold, else the branch is skipped with a reason):**
   - tip is an ancestor of `origin/main` (fully merged);
   - not protected: `main`, `staging`, `relay-channel`, `supervisor-state`, `decisions-tools`, `cleanup-request`,
     `archive/**`, `backup/**`, `codex/**`, or a branch named in an open row of `docs/process/TASK_LOG.md`;
   - a backup exists: the tip is reachable from a `backup/*` tag or an `archive/backup-*` branch, and the latest
     `backup.yml` run on main concluded `success` (if `backup.yml` has never run, refuse: no backup = no delete);
   - `mode: delete` is accepted only if a dry run for the same request content succeeded earlier (record the
     request hash in the dry-run log).
3. **Logging:** every run writes its decision table to the job summary; each deletion appends
   `date | branch | sha | request hash` to `docs/process/CLEANUP_LOG.md` (committed by the workflow to
   `cleanup-request`, never to main). Restore line documented: `git push origin <sha>:refs/heads/<name>`.
4. **Tests (gate + CI):** `tools/cleanup/select.py` holds all decision logic as pure functions;
   `tools/cleanup/tests/test_select.py` builds a scratch repository and covers: merged, unmerged, merged-then-new-
   commit, each protected name/pattern, open-task branch, missing backup, failed/never-run backup, delete without
   prior dry run, unknown branch name. End-to-end test on throwaway `cleanup-test/*` branches in CI: create, merge into
   a scratch base, run selection + deletion against a local bare clone, restore from the log, verify the SHA.
   Register the tests in `tools/check_all.py` **only via a single line agreed in your report** — T-041 owns
   `check_all.py`, so instead provide `tools/cleanup/run_tests.py` and the Supervisor wires it in after both merge.
5. **First real use (Supervisor):** a dry run over the merged branches listed in `/docs/process/TASK_LOG.md`
   history; deletion only after the dry run is reviewed.
6. Docs: `docs/process/CLEANUP.md` (how to request, how it decides, how to restore).
