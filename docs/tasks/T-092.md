## Acceptance criteria
1. **New opt-in preset family `presets/3`** (new ids in a new library file, like T-066's skin family): quiet trouser
   pile, soft hoodie fleece, dense smooth vest felt, cream fleece boot cuffs, and a warmer skin in shadow and on the
   hands. Every presets/1 and presets/2 id resolves and builds exactly as on `main` (test: node graphs and swatch
   renders of all existing ids unchanged).
2. **One uniform fibre halo per preset** through the existing shared Geometry Nodes fibre group
   (`PS Shared Surface Fibres/1`); no new fibre system.
3. **Fixed lights:** every preset judged under neutral (`character_neutral/1`) and one warm rig of
   `pipeline/charsys/render_calibration.json` (read-only; a new rig only as a new entry of this task's own data file).
4. **Patches:** per material a macro patch and a shot-size patch (same camera distance as the strict-sheet body rows);
   colour ΔE to the reference targets before → after; **render time per patch and per strict sheet recorded**.
5. **Candidate overrides** per character in this task's own candidate folder: they change only material
   assignments (`materials.assignments` and the `material` entries of garments). No edit to any `*.spec.json` or
   published version; no version bump (T-094). If an override must carry the `clothing.garments` list (lists are
   replaced, not merged), it changes only `material` keys, so T-094 can combine it with T-093 field by field.
6. **Visual deliverable:** one cheap first frame (`recipe.py preview`), then one T-087 strict sheet per character
   plus the patch sheet; owner evidence in `docs/evaluation/materials/T-092/`.
7. Tests for 1–2. No test loosened, no frozen or published file changed. New tests are listed in the READY report;
   the Supervisor wires them into the gate at merge.
