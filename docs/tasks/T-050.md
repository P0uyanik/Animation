# T-050: GPU / render cost study (no spending)
Study · docs only · branch `t-050-claude-render-cost` from `origin/staging`

## Goal
Know what finished episodes cost to render and which option is best before any money is spent.

## Deliverable
1. Measure today's CPU Cycles cost in this container on existing shots (e.g. e906, a turnaround still): seconds per
   frame at the samples/resolution/denoise settings we use, and at the target final quality (1080p, benchmark look);
   extrapolate to a 2.5 min episode at 24/30 fps, incl. re-renders (assume 3 renders per shot).
2. Options with cost per finished minute and turnaround time, using current public prices (cite sources and date):
   owner's own GPU (which cards suffice; Cycles OptiX/CUDA benchmark scores), cloud GPU rental (on-demand and spot),
   render farms, Eevee Next for previews/blocking, adaptive sampling + OIDN budgets, persistent data / caching.
3. Quality check: an identical still at matched noise via CPU vs reduced-sample + OIDN (and Eevee) to show what
   cheaper settings cost visually (render budget ≤ 8 stills).
4. Recommendation for (a) daily previews, (b) owner review renders, (c) final episodes, with a monthly cost estimate.
   **No purchase, sign-up or paid API use.**
5. Report `docs/evaluation/render/T-050/README.md`.
