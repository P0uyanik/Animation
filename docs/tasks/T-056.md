# T-056: order-stable, byte-reproducible engine export
Lane B · path A (zero character change) · branch `t-056-claude-export-determinism` from `origin/staging`

## Why
T-043 found that two exports of the same character at the same commit differ (`geometry.bin`: vertex/triangle order of
some meshes, ≤ 4e-5 float noise in evaluated normals; `docs/evaluation/characters/T-043/README.md` §6). T-041's CI also
shows the boy's `hair_clumps` export differing. The unchanged-character guard (DELIVERY_PLAN §5.2) needs exports that
are byte-identical across builds.

## Acceptance criteria
1. `pipeline/charsys/export_engine.py` (and helpers it owns) writes meshes in a canonical, run-independent vertex and
   triangle order and quantises evaluated normals/positions deterministically (document the grid; no visible change),
   so two clean builds + exports of every character produce byte-identical packages (`geometry.bin`, manifest JSON).
   Fix the source of order variation where possible rather than only sorting at the end.
2. The engine loads and plays the new export identically (plush_tests, CTest, shot bake of e904 unchanged within
   existing tolerances); bump the exporter's per-feature version per `docs/CHARACTER_SYSTEM_VERSIONS.md` (new version
   is default for new exports; character pins follow that document's rules).
3. Proof: 3 consecutive build+export runs per character, byte-identical; geometry fingerprints unchanged; full gate PASS.
