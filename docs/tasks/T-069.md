# T-069: codebase audit — outdated, deprecated, unused, duplicate and legacy code/assets (report only)
Evaluation only (no deletions, no code changes) · branch `t-069-claude-legacy-audit` from `origin/staging`

## Why (owner request 2026-11-17)
"Does our main branch contain any outdated, deprecated, or unused code, character versions, or legacy systems?
Please audit the codebase and identify anything that is no longer needed, including duplicate implementations."

## Deliverable: `docs/evaluation/review/T-069/README.md`
1. **Inventory** of candidates across the whole repo (engine C++, apps, pipeline/charsys, pipeline/blender, pipeline/clips,
   pipeline/production, tools, content, assets, docs, tests, root files such as CURRENT_STATUS.md/NEXT_TASK.md, build/
   logs, pip.log, imgui.ini, __pycache__): unused modules/functions (no importer/caller — show the search), dead
   scripts (one-off make_*/render_* tools), superseded systems (e.g. body_v6 vs body_generic, hair.py legacy vs groom,
   legacy character JSONs in content/characters, old engine-era characters, old evaluation shots), duplicate
   implementations (same logic in two places — name both and which is canonical), stale docs that contradict current
   process, committed generated files, large binaries.
2. **Classification** per item, with evidence:
   - **Keep (required):** frozen assets/baselines (`tools/frozen_manifest.txt`), regression references, anything a
     test or the gate still uses, published character versions (boy 1.0.0/1.1.0, girl versions).
   - **Remove (safe):** no references anywhere, not frozen, not needed for reproducing published versions.
   - **Consolidate:** duplicates — which to keep, migration steps.
   - **Archive:** historically useful but not used (move to an archive folder or tag).
   - **Owner decision:** anything ambiguous (e.g. old characters that might return).
3. **Risk notes:** what each removal could break; which tests/gate checks prove it safe.
4. **Cleanup plan:** small, conflict-free tasks in an order that avoids running tasks' files (see
   docs/process/OWNERSHIP.md), with expected size/repo-weight savings.

## Rules
Read-only except the report. Use git grep / import graphs / build files to prove "unused". Never propose removing
frozen or regression-reference files. Be honest about uncertainty.
