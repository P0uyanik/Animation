## Why (evidence)
`docs/audit/T-176/REPORT.md` W1 and proposal row 3: 29 of 31 `main` gate runs in 8.5 h were for docs-only ledger commits,
and each `main` move forced integration branches to re-merge and re-gate. Risk note in §5 "A wrong fast path (3)".

## Acceptance criteria
1. A push to `main` or `staging` whose changed paths are ALL under `docs/process/**` or `docs/tasks/**` runs a short
   job only (target ~1 min): doc links (`tools/check_doc_links.py`), OWNERSHIP parse (`tools/integrate.py claims --list`),
   `python3 tools/regression/tests/test_gate_tools.py`. ANY other path (or a mix) runs the full gate exactly as today.
2. The decision is made from the changed-path list alone (extend `tools/regression/tiers.py` or add a sibling classifier);
   no content heuristics, no commit-message markers.
3. Promotion (`tools/ci_status.py` verified / the promote step in `docs/process/GATE.md`) accepts an integration commit
   whose diff against a green `main` commit touches only those two folders, citing the green run of that `main` commit.
4. Tests for the classifier: docs-only → fast; mixed docs + any other path → full; a path that merely resembles the
   prefixes (`docs/processX/…`, `docs/tasks.md`, `docs/evaluation/**`) → full; renames/deletes counted by both sides;
   empty diff → full. Add them to the existing `tools/regression/tests/test_gate_tools.py` (no new test file, so no
   registration line).
5. Nothing weakened: task, integration and PR runs keep their current tiers; no check removed from the full gate;
   Blender shards and the Windows gate unchanged for non-docs pushes. Show one real docs-only push run and one mixed run
   (on your branch via a dispatch or a scratch branch) in the README.
6. `docs/process/GATE.md` gets a short "docs-only fast path" section.
