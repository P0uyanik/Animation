# T-074: CPU-only Blender render optimisation (study, then presets)
Implementer: Claude (cloud) · lane E (render) · study · branch `t-074-claude-cpu-render` from `origin/staging`
Owner decision 2026-11-17: optimise Blender rendering for CPU-only use, **final visual quality first**; evaluate
Eevee, Cycles, denoising and other free options. No GPU rental, no purchases.

## Why
Final shots render in Blender Cycles (TD-42) on CPU. A 2–2.5 min episode must be renderable in practical time
without losing the plush/felt look (fibre halo, fleece sheen, skin softness, hair) the references show.
Builds on T-050 (`docs/evaluation/render/T-050/`, cost model `cost_model.py`).

## Acceptance criteria
1. **Quality reference:** a high-sample Cycles still per test view (current approved boy 1.1.0 and girl 0.10.0, cast
   `"current"`; close-up face, medium shot, full body; plus one hair/fleece macro). These are the ground truth.
2. **Options measured against the reference** (s/frame at 1080p, peak RAM, and a visual diff + side-by-side sheet):
   - Cycles: adaptive sampling + noise threshold, sample budgets, OIDN (with albedo/normal passes, prefilter modes),
     light-path/bounce limits, caustics/clamping, light tree, persistent data and tiling for animation, path-guiding
     on CPU, simplification of hair/fibre children per shot distance;
   - Eevee (Next): which materials/hair/fibres survive, for previews/blocking and whether any final shots qualify;
   - Workbench/Eevee for animation previews; resolution/frame-rate drafts;
   - denoising across frames (temporal stability/flicker over ≥ 24 frames, not only stills).
3. **Recommendation** as named profiles (e.g. `preview`, `review`, `final`) with expected s/frame, episode estimate
   (T-050 model), and the visual cost of each saving. `final` must be visually indistinguishable from the reference
   at viewing size in side-by-side sheets; anything that softens fibres, sheen or hair is rejected.
4. Study only: **no changes** to shared render code, materials, presets or calibration. Turning the profiles into
   code is a follow-up task (path B: owner approves renders) scheduled before the benchmark scene.
5. Evidence per DELIVERY_PLAN §9b; report `docs/evaluation/render/T-074/README.md`.
