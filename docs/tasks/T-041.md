# T-041 (+T-042): gate on GitHub, file claims, full regression, unchanged-character guard, durable backups
Lane A · path A (technical) · plan: docs/process/DELIVERY_PLAN.md §3, §5, §8.1 · branch `t-041-claude-gate-claims` from `origin/staging`

## Goal
Make the delivery plan's safety rules executable: they must run in `tools/check_all.py` and in GitHub CI.

## Acceptance criteria
1. **CI green on GitHub runners:** `.github/workflows/checks.yml` passes on `staging` (ubuntu at minimum); Blender
   tier runs in CI or is explicitly reported as "local-only" by the gate (never silently skipped). Add `staging`
   to its push branches. Cache builds; total CI time documented.
2. **File claims:** `docs/process/OWNERSHIP.md` (claims table: task, write-set globs, depends-on, versions bumped) and
   `tools/integrate.py claims --check T-NNN` (overlap = exit 1, glob-aware), plus `stage`, `promote`, `--dry-run`
   (trial merge, gate, `--no-ff` merge into staging; promote = fast-forward main + backup tag first).
3. **Write-set enforcement:** gate check "Write-set" fails when the diff vs `origin/staging` leaves the task's claim.
4. **Path classification:** one guarded file (`tools/regression_paths.txt`) maps paths → fast / full; unknown → full.
5. **Full regression + unchanged-character guard (plan §5.1/5.2):** for every character in `assets/characters`:
   build, fingerprint (`pipeline/charsys/fingerprint_v2.py`), engine export, fixed-camera regression renders
   (turnaround + face close-up, low samples, fixed seed) vs approved baselines, fidelity. Characters whose spec did
   not change must be identical to `origin/main` (fingerprints byte-equal; renders within a noise threshold you
   measure on two identical builds and record). Per-character jobs run in parallel.
6. **Durable backups (plan §8.1 layers 1–2):** cloud sessions cannot push tags (proxy 403), so backup tags `backup/<UTC date-time>/<branch>` are created by a GitHub Actions job (contents: write) triggered by
   every push to `main`/`staging` and by a backup request; until then `archive/backup-<date>-<branch>` branches are used. `backup.yml` makes a verified bundle + SHA-256 on every main push and nightly, uploads it
   as an artifact, creates a weekly `backup-<date>` release, and runs a restore test (clone bundle, compare all
   branch SHAs with the remote, run the fast tier).
7. `tools/simulate_quality_gate.py` extended with simulations for: claim overlap, write-set violation, unknown path
   → full, changed unchanged-character fingerprint → FAIL. All simulations PASS.
