# Motion Capture Source Formats: ACCAD and CMU

This document specifies the technical formats, joint hierarchies, units, coordinate conventions, and rest poses for motion capture (mocap) datasets from **ACCAD** (Advanced Computing Center for the Arts and Design, The Ohio State University) and **CMU** (Carnegie Mellon University Graphics Lab Motion Capture Database). It defines the joint mapping to the shared roles in `pipeline/charsys/rig_profiles/humanoid_rigify.json` for the Plush animation clip pipeline (`docs/ANIMATION_CLIPS.md` §8).

All data documented here is derived directly from official repository pages, official format documentation, and official sample data files. Elements relying on third-party conventions rather than official source files are explicitly designated as **[UNVERIFIED - Community Conversion]**.

## 1. ACCAD (The Ohio State University)

### 1.1 Source & Repository Documentation
- **Institution:** Advanced Computing Center for the Arts and Design (ACCAD), The Ohio State University.
- **Official Portal:** [ACCAD MoCap System and Data](https://accad.osu.edu/research/motion-lab/mocap-system-and-data)
- **Licence:** Creative Commons Attribution 3.0 Unported License (CC BY 3.0) via ACCAD Open Motion Project.
- **Hardware:** 12-camera optical tracking system (Vicon Valkyrie and legacy Vicon MX-40 / Vicon IQ) capturing retroreflective markers (typically 41 markers).
- **Software Pipeline:** Vicon Shogun / Vicon IQ $\rightarrow$ Autodesk MotionBuilder $\rightarrow$ Maya / Unity 3D / Unreal Engine.
- **Verified Sample Archives:**
  - `Female1_bvh.zip` (81 BVH files, e.g. `Female1_C21_S2_RunToPickUpBox.bvh`)
  - `Male1_bvh.zip` (69 BVH files, e.g. `Male1_C22_RunWithBox.bvh`)
  - `Male2_bvh.zip` (149 BVH files, e.g. `Male2_G4_SpinningBackKick.bvh`)
  - `Female1General_c3d.zip` (18 C3D files, e.g. `A1 - Stand.c3d`)
  - Legacy takes: `walkdog_BVH.ZIP` (`ericdog.bvh`), `walkdog_AMC.ZIP`, `camper04_C3D.ZIP`.

### 1.2 File Formats
- **BVH (.bvh - Biovision Hierarchy):**
  - **Status:** Primary skeletal distribution format on ACCAD for human movement (`Female 1`, `Male 1`, `Male 2`).
  - **Structure:** ASCII text format containing two sections: `HIERARCHY` (defines joint offsets, parent-child links, and channel layout) and `MOTION` (frame count, frame time, and frame-by-frame Euler rotations/translations).
  - **Generation:** Generated by solving optical marker data onto a standard biped skeleton in Autodesk MotionBuilder.
- **C3D (.c3d - Coordinate 3D):**
  - **Status:** Primary raw optical marker trajectory format.
  - **Structure:** Standard biomechanics binary format containing 3D marker coordinate streams.
  - **Contents:** Marker trajectories (41 physical retroreflective markers following the Vicon Plug-in Gait template, e.g. `LFHD`, `RFHD`, `LBHD`, `RBHD`, `C7`, `T10`, `CLAV`, `LFWT`, `RFWT`, etc.). C3D files contain point cloud trajectories and do not define a kinematic joint hierarchy.
- **FBX (.fbx - Filmbox):**
  - **Status:** Documented by ACCAD as the main export option for DCC tools (MotionBuilder, Maya, Unity 3D, Unreal Engine).
  - **Structure:** Autodesk proprietary binary/ASCII format bundling optical markers, skeleton hierarchy with rotation/translation channels, skinned meshes, vertex colors, and virtual cameras. Note: Pre-exported FBX files are not distributed as standalone downloads on the public ACCAD sample page; FBX is documented as the studio's primary exchange export from MotionBuilder.
- **Secondary / Legacy Formats on ACCAD:**
  - **AMC / ASF (.amc, .asf):** Acclaim formats provided for specific legacy figure takes (e.g. `walkdog_AMC.ZIP`, `handspring_AMC.ZIP`, `quickwalk_AMC.ZIP`, `sprint_AMC.ZIP`, `swagger_AMC.ZIP`).
  - **TXT (.txt):** Plain text comma- or space-delimited XYZ translation coordinates derived directly from C3D data via Vicon Blade software.
  - **TVD (.tvd):** Vicon tracking volume display/visualization files.
  - **MOV (.mov):** 320×260 preview reference movies.
  - **PDF (.pdf):** Catalog / take lists indexing performer actions and subject calibration.

```text

└── JOINT ToSpine
    └── JOINT Spine
        └── JOINT Spine1
            ├── JOINT Neck
            │   └── JOINT Head
            │       └── End Site
            ├── JOINT LeftShoulder
            │   └── JOINT LeftArm
            │       └── JOINT LeftForeArm
            │           └── JOINT LeftHand
            │               └── End Site
            └── JOINT RightShoulder
                └── JOINT RightArm
                    └── JOINT RightForeArm
                        └── JOINT RightHand
                            └── End Site
└── JOINT LeftUpLeg
    └── JOINT LeftLeg
        └── JOINT LeftFoot
            └── JOINT LeftToeBase
                └── End Site
└── JOINT RightUpLeg
    └── JOINT RightLeg
        └── JOINT RightFoot
            └── JOINT RightToeBase
```

*Note on legacy takes:* Re-targeted figure takes such as `walkdog_BVH.ZIP` (`ericdog.bvh`) use an alternative hierarchy derived from Acclaim naming conventions (`lowerback`, `upperback`, `thorax`, `neck`, `head`, `lshoulderjoint`, `lhumerus`, `rfemur`, etc.).

### 1.4 Units, Axis Conventions & Frame Rate
- **Units:**
  - **BVH:** **Centimeters (cm)**. Verified directly from joint offsets across `Female1`, `Male1`, and `Male2`:
    - Pelvis height (`Hips` Y-offset): ~91.1 cm (`Female1`), ~98.9 cm (`Male1`), ~101.6 cm (`Male2`).
    - Thigh (`LeftLeg` relative to `LeftUpLeg`): ~44.1 cm.
    - Shin (`LeftFoot` relative to `LeftLeg`): ~36.2 cm (`Female1`) / ~46.6 cm (`Male1`).
    - Upper arm (`LeftForeArm` relative to `LeftArm`): ~19.0 cm.
    - Forearm (`LeftHand` relative to `LeftForeArm`): ~23.0 cm (`Female1`) / ~27.5 cm (`Male1`).
  - **C3D:** **Millimeters (mm)**. Verified from `POINT:UNITS` parameter block in `A1 - Stand.c3d`.
  - **FBX:** [UNVERIFIED - Community Conversion / Pipeline Dependent] Configurable in MotionBuilder/Maya export profiles, typically centimeters.
- **Axis Conventions (BVH):**
  - **Coordinate System:** Right-handed Cartesian.
  - **+Y:** Upward (spine, neck, head offsets are positive in Y).
  - **+X:** Character's Left (LeftShoulder, LeftArm, LeftForeArm, LeftHand offsets are positive along X).
  - **-X:** Character's Right (RightShoulder, RightArm, RightForeArm, RightHand offsets are negative along X).
  - **+Z:** Forward (character facing direction; `LeftToeBase` and `RightToeBase` offsets are +13.0 cm in Z).
  - **Rotation Channel Order:** `Zrotation Xrotation Yrotation` (ZXY Euler order) on all joints.
  - **Root Channels:** 6 channels (`Xposition Yposition Zposition Zrotation Xrotation Yrotation`).
- **Axis Conventions (C3D):**
  - Optical marker coordinates: `X_SCREEN = +X`, `Y_SCREEN = +Z` (Z-up in raw optical space), units `mm`.
- **Frame Rate:**
  - **BVH:** **30 fps** (`Frame Time: 0.0333333` s verified across all `Female1`, `Male1`, `Male2` files).
  - **C3D (Raw Optical Capture):** **120 Hz / 120 fps** (`POINT:RATE = 120.0` Hz verified from C3D parameter headers). Resampled to 30 fps during MotionBuilder BVH solve.

### 1.5 Rest Pose / T-Pose Convention
In ACCAD BVH files, when all rotation channels are zero ($0.0^\circ$):
- Torso, neck, and head extend vertically along **+Y**.
- Arms extend horizontally straight out along the X-axis: left arm along **+X**, right arm along **-X**.
- Legs extend vertically straight down along **-Y**.
- Feet and toes extend forward along **+Z**.
- Palms face downward (along -Y).
This represents a standard **T-pose**, directly matching the Plush character reference pose specification (`humanoid_rigify.json`).

## 2. CMU Graphics Lab Motion Capture Database

### 2.1 Source & Repository Documentation
- **Institution:** Carnegie Mellon University (CMU) Graphics Lab.
- **Official Portal:** [CMU Graphics Lab Motion Capture Database](http://mocap.cs.cmu.edu/)
- **Documentation & References:**
  - FAQs: `http://mocap.cs.cmu.edu/faqs.php`
  - Info & Mocap Process: `http://mocap.cs.cmu.edu/info.php`
  - Tools & Software: `http://mocap.cs.cmu.edu/tools.php`
  - Specification Reference: [University of Wisconsin ASF-AMC Specification](http://www.cs.wisc.edu/graphics/Courses/cs-838-1999/Jeff/ASF-AMC.html)
- **Licence:** Supported by NSF Grant #0196217. Free for all uses ("may be copied, modified, or redistributed without permission").
- **Hardware:** 12 Vicon MX-40 infrared cameras recording at 120 Hz, 4 megapixel resolution, ~3 m × 8 m capture volume.
- **Marker Set:** 41 retroreflective markers on a black jumpsuit (Plug-in Gait marker placement; LFIN/RFIN markers placed on the knuckle of the middle finger).
- **Verified Sample Data:** Subject 01 (`01.asf`, `01_01.amc`).

### 2.2 File Formats
- **ASF / AMC (.asf, .amc - Acclaim Skeleton File / Acclaim Motion Capture):**
  - **Status:** Primary native skeletal format created and distributed directly by CMU Graphics Lab.
  - **ASF (.asf):** ASCII text file defining subject-specific skeletal kinematics (`:bonedata` and `:hierarchy`), bone lengths, directions, local coordinate systems (`axis`), degrees of freedom (`dof`), and joint angle limits (`limits`).
  - **AMC (.amc):** ASCII text file containing frame-by-frame motion stream. Specifies root translation (`TX TY TZ`) and root rotation (`RX RY RZ`), followed by the active rotational degrees of freedom (Euler angles in degrees) for each joint per frame.
- **C3D (.c3d - Coordinate 3D):**
  - **Status:** Raw 3D optical marker trajectories recorded directly from the Vicon system.
  - **Structure:** Standard biomechanics binary format. Contains 41 raw physical marker trajectories plus auxiliary model output markers generated during Vicon BodyBuilder conversion.
- **Vicon Internal Formats (.vsk, .v, .trial):**
  - Used internally during ViconIQ processing and skeleton fitting (`.vsk` subject skeleton template, `.v` motion stream).
- **BVH (.bvh - Biovision Hierarchy):**
  - **Status:** [UNVERIFIED - Community Conversion] Not natively authored or distributed by CMU. Officially acknowledged and linked via `mocap.cs.cmu.edu` home page and FAQs as third-party conversions (notably Bruce Hahne's cgspeed conversions for 3ds Max Biped and MotionBuilder).
- **FBX (.fbx):**
  - **Status:** [UNVERIFIED - Community Conversion] Not distributed by CMU; available via community conversion pipelines.
- **Video Previews:**
  - MPEG (`.mpg`) and AVI (`.avi`) reference movies for each trial.

### 2.3 Joint Hierarchy & Bone Names (CMU Native ASF)
The native CMU skeleton defined in `01.asf` contains 31 bones (1 root + 30 bones):

```text
root
├── lowerback
│   └── upperback
│       └── thorax
│           ├── lowerneck
│           │   └── upperneck
│           │       └── head
│           ├── lclavicle
│           │   └── lhumerus
│           │       └── lradius
│           │           └── lwrist
│           │               ├── lhand
│           │               │   └── lfingers
│           │               └── lthumb
│           └── rclavicle
│               └── rhumerus
│                   └── rradius
│                       └── rwrist
│                           ├── rhand
│                           │   └── rfingers
│                           └── rthumb
├── lhipjoint
│   └── lfemur
│       └── ltibia
│           └── lfoot
│               └── ltoes
└── rhipjoint
    └── rfemur
        └── rtibia
            └── rfoot
                └── rtoes
```

*Key structural characteristics:*
- `lhipjoint` and `rhipjoint`: Rigid pelvic extension segments (length ~2.4 in, 0 DOFs) connecting `root` to hip sockets.
- `lwrist` and `rwrist`: 1-DOF (`dof ry`, limits `[-180.0, 0.0]`) forearm twist/wrist roll segments preceding `lhand`/`rhand`.
- `lfingers` and `rfingers`: Single lumped finger segment with 1 DOF (`dof rx`, limits `[0.0, 90.0]`).
- `lthumb` and `rthumb`: Single 2-DOF thumb segment (`dof rx rz`, limits `[-45.0, 45.0]`).

### 2.4 Units, Axis Conventions & Frame Rate
- **Units:**
  - **ASF / AMC:** Length unit is **inches**, scaled by factor `0.45` in the file header (`:units length 0.45`).
    - **Official Metric Conversion Formula (from CMU FAQ):**
      $$\text{scale} = \left(\frac{1.0}{0.45}\right) \times \frac{2.54}{100.0} \approx 0.0564444\text{ meters per unit}$$
    - Rotational units: **Degrees** (`:units angle deg`).
    - Mass unit: Default `1.0` (`:units mass 1.0`).
  - **C3D:** **Millimeters (mm)**.
- **Axis Conventions:**
  - **World Coordinate Frame:** Right-handed Cartesian, **+Y up**.
    - **+Y:** Upward.
    - **+Z:** Forward (character facing direction; `ltoes` direction is `[0, 0, 1]`, `lfoot` direction is `[0.067, -0.183, 0.981]`).
    - **+X:** Character's Left (`lhumerus` direction is `[1, 0, 0]`, `lradius` direction is `[1, 0, 0]`).
    - **-X:** Character's Right (`rhumerus` direction is `[-1, 0, 0]`, `rradius` direction is `[-1, 0, 0]`).
  - **Local Bone Axes:** Specified individually per bone in `:bonedata` via the `axis` parameter (Euler rotation order, e.g. `180 -30 -90 XYZ` for `lhumerus`). AMC frame rotations rotate around these local bone axes.
- **Frame Rate:**
  - **Native Capture & AMC:** **120 Hz / 120 fps** (captured via 12 Vicon MX-40 cameras).
  - **Community BVH Conversions:** [UNVERIFIED - Community Conversion] Frequently resampled to 30 fps, 60 fps, or preserved at 120 fps.

### 2.5 Rest Pose / T-Pose Convention
In the CMU ASF specification, when all joint rotation channels in the AMC motion file are set to zero ($0.0^\circ$):
- Bone direction vectors in `:bonedata` define the rest orientation:
  - Spine, neck, and head bones (`lowerback`, `upperback`, `thorax`, `lowerneck`, `upperneck`, `head`) point vertically upward along **+Y** ($\approx [0, 1, 0]$).
  - Left arm chain (`lhumerus`, `lradius`, `lwrist`, `lhand`, `lfingers`) points horizontally outward along **+X** ($[1, 0, 0]$).
  - Right arm chain (`rhumerus`, `rradius`, `rwrist`, `rhand`, `rfingers`) points horizontally outward along **-X** ($[-1, 0, 0]$).
  - Thighs and shins (`lfemur`, `ltibia`, `rfemur`, `rtibia`) point vertically downward along **-Y** ($\approx [\pm 0.342, -0.940, 0]$, slightly spread).
  - Feet and toes (`lfoot`, `ltoes`, `rfoot`, `rtoes`) point directly forward along **+Z** ($[0, 0, 1]$).
  - Thumbs (`lthumb`, `rthumb`) point forward-outward at 45° in the horizontal plane ($\approx [\pm 0.7071, 0, 0.7071]$).
- This zero-rotation stance constitutes an exact **T-pose**, matching the reference pose definition in `pipeline/charsys/rig_profiles/humanoid_rigify.json`.

## 4. Retargeting Guidelines for Plush Clip Converter

Following the converter specification in `docs/ANIMATION_CLIPS.md` §8:
1. **Rest Frame Calculation:**
   Compute the source skeleton's rest frames using direction-to-child and twist hints, matching `deriveRetarget`.
2. **Unit Normalization:**
   - ACCAD BVH coordinates must be scaled by $0.01$ (centimeters $\rightarrow$ meters).
   - CMU ASF/AMC translations and bone lengths must be scaled by $\frac{1.0}{0.45} \times \frac{0.0254}{1.0} \approx 0.0564444$ (scaled inches $\rightarrow$ meters).
3. **Hierarchy Folding:**
   Intermediate bones (`ToSpine` in ACCAD; `upperback`, `upperneck`, `lwrist` in CMU) should have their local rest and animated transformations composed into their parent or omitted if non-rotational.
4. **Foot Planting & Root Scaling:**
   Root motion translation must be divided by the source leg length (hip to ankle distance in meters) to match the target character scale.
